# password-policy

`password-policy` — CLI-инструмент на Go для генерации и проверки паролей по декларативной политике, аудита списков паролей и выдачи паролей субъектам с учётом истории и срока действия.

Имя CLI-команды — `pwp`.

Инструмент работает локально и не требует обращения к сети или внешним сервисам.

# Сборка и установка

Минимальная версия Go:

```text
Go 1.20
```

Сборка под Linux:

```bash
go build -o pwp ./cmd/pwp
```

Сборка под Windows:

```powershell
go build -o pwp.exe ./cmd/pwp
```

Также проект поддерживает сборку через `Makefile`:

```bash
make build
```

Для установки через Go:

```bash
go install ./cmd/pwp
```

# Схема политики

Политика задаётся в YAML или JSON.

Формат определяется по расширению файла:

```text
.yaml
.yml
.json
```

Если расширение отсутствует, формат определяется по содержимому.

Пример политики:

```yaml
version: 1

policy:
  name: service-accounts

  length:
    min: 16
    max: 24

  classes:
    - name: digits
      alphabet: "0123456789"
      min: 2

    - name: lower
      alphabet: "abcdefghijklmnopqrstuvwxyz"
      min: 2

    - name: upper
      alphabet: "ABCDEFGHIJKLMNOPQRSTUVWXYZ"
      min: 2

    - name: special
      alphabet: "!@#$%^&*()-_=+[]{};:,.?"
      min: 1

  exclude: "lI1O0"

  attempts: 100

  forbid:
    repeat_run: 2
    repeat_total: false

    sequences:
      alphabet: 3
      keyboard: 3
      layouts:
        - qwerty
        - jcuken

    dictionary:
      path: dict/common.txt
      min_length: 4
      case_insensitive: true
      leet: true

    context:
      min_length: 3

issue:
  pool_size: 64
  store: data/history

  history:
    window: 5
    ttl: 180d

  rotate_after: 90d
```

## Основные правила разбора

* `version` обязателен и должен быть равен `1`;
* `policy.name` обязателен;
* в `policy.name` допустимы `A-Z`, `a-z`, `0-9`, `-` и `_`;
* список `classes` не может быть пустым;
* имена классов должны быть уникальными;
* неизвестное поле является ошибкой;
* дублирующийся YAML-ключ является ошибкой;
* отсутствующие необязательные поля получают значения по умолчанию.

## Значения по умолчанию

| Поле                                 | Значение по умолчанию                 |
| ------------------------------------ | ------------------------------------- |
| `length.min`                         | `12`                                  |
| `length.max`                         | равно `length.min`                    |
| `classes[].min`                      | `0`                                   |
| `exclude`                            | пусто                                 |
| `attempts`                           | `100`                                 |
| `forbid.repeat_run`                  | `0`, ограничение отключено            |
| `forbid.repeat_total`                | `false`                               |
| `forbid.sequences.alphabet`          | `0`, ограничение отключено            |
| `forbid.sequences.keyboard`          | `0`, ограничение отключено            |
| `forbid.sequences.layouts`           | `[qwerty]`                            |
| `forbid.dictionary`                  | не задан, проверка отключена          |
| `forbid.dictionary.min_length`       | `4`                                   |
| `forbid.dictionary.case_insensitive` | `true`                                |
| `forbid.dictionary.leet`             | `false`                               |
| `forbid.context.min_length`          | `3`                                   |
| `issue.pool_size`                    | `16`                                  |
| `issue.store`                        | не задан                              |
| `issue.history.window`               | `0`, запрет повторной выдачи отключён |
| `issue.history.ttl`                  | `0s`, срок хранения не ограничен      |
| `issue.rotate_after`                 | `0s`, ротация не планируется          |

Длительность задаётся целым неотрицательным числом с одним из суффиксов:

```text
s
m
h
d
```

`d` означает ровно 24 часа.

Примеры:

```text
30s
15m
24h
90d
180d
```

Значение без суффикса и отрицательное значение являются ошибкой.

# Алфавиты и классы

Алфавит каждого класса задаётся строкой.

Правила построения:

1. повторяющийся символ внутри алфавита одного класса является ошибкой;
2. из каждого класса удаляются символы из `exclude`;
3. класс, ставший пустым после `exclude`, является ошибкой;
4. алфавиты разных классов не должны пересекаться;
5. символ должен принадлежать ровно одному классу;
6. алфавиты обрабатываются как последовательности Unicode-рун, а не байтов;
7. комбинирующие Unicode-символы в алфавите запрещены;
8. внутренний порядок алфавита нормализуется, поэтому порядок символов в исходной строке не должен влиять на результат.

# Разрешимость политики

Разрешимость проверяется до начала генерации.

Неразрешимая политика должна завершать работу с кодом `2`, а генерация для неё не запускается.

Основные условия разрешимости:

1. `length.min` и `length.max` больше нуля;
2. `length.min <= length.max`;
3. сумма всех `classes[].min` не превышает `length.max`;
4. каждый класс после применения `exclude` остаётся непустым;
5. классы не пересекаются;
6. при `repeat_total: true` значение `length.max` не превышает размер объединённого алфавита;
7. при `repeat_total: true` значение `min` отдельного класса не превышает размер его алфавита;
8. `attempts` больше нуля;
9. если задан `forbid.dictionary.path`, файл словаря должен существовать и читаться;
10. при `issue.history.window > 0` нижняя граница энтропии политики должна быть не меньше:

```text
log2(history.window) + 10
```

Если это условие не выполняется, политика считается слишком узкой для заданного окна истории.

# Источник случайности и выборка без смещения

Рабочая генерация использует криптографический источник:

```go
crypto/rand.Reader
```

Источник случайности передаётся через интерфейс:

```go
type Source interface {
    Read(p []byte) (int, error)
}
```

Выбор случайного значения из диапазона `[0, n)` выполняется выборкой с отбрасыванием — rejection sampling.

Использование простого:

```text
randomValue % n
```

для выбора индекса запрещено, поскольку при диапазоне источника, не делящемся на `n` без остатка, это создаёт modulo bias.

Алгоритм выбирает минимальное число случайных байтов, покрывающее диапазон, и отбрасывает значения, попавшие в неполный последний участок диапазона.

Перемешивание пароля выполняется алгоритмом Fisher-Yates, а индексы для него выбираются тем же способом без смещения.

# Алгоритм генерации

Одна попытка генерации состоит из следующих шагов:

1. равномерно выбрать длину `L` из диапазона `[length.min, length.max]`;
2. для каждого класса выбрать `min` символов;
3. заполнить оставшиеся позиции символами из объединённого алфавита;
4. перемешать полученную последовательность;
5. проверить все правила `forbid`;
6. если найдено нарушение — начать следующую попытку.

При:

```yaml
repeat_total: true
```

символы на этапах заполнения выбираются только из ещё не использованных.

Количество попыток ограничено:

```yaml
attempts: 100
```

Если все попытки исчерпаны, генерация завершается ошибкой:

```text
policy_too_strict
```

с кодом возврата `2`.

При неудаче политика не ослабляется: длина, минимумы классов и запреты не изменяются.

Пароль формируется как `[]byte`.

# Правила запретов

## `repeat_run`

```yaml
repeat_run: 2
```

Запрещены `n + 1` и более одинаковых символов подряд.

Например, при `repeat_run: 2`:

```text
aaa
!!!
```

являются нарушениями.

## `repeat_total`

```yaml
repeat_total: true
```

Каждый символ может встречаться в пароле не более одного раза.

## Алфавитные последовательности

```yaml
sequences:
  alphabet: 3
```

Запрещаются последовательности длиной `k` и более, идущие по коду руны в прямом или обратном направлении.

Примеры:

```text
abc
cba
123
321
```

Проверка выполняется без учёта регистра, поэтому:

```text
aBc
```

также является последовательностью.

## Клавиатурные последовательности

```yaml
sequences:
  keyboard: 3
  layouts:
    - qwerty
    - jcuken
```

Значение `keyboard` задаёт минимальную длину запрещённой клавиатурной последовательности. Значение `0` отключает проверку.

Запрещаются последовательности длиной `k` и более, идущие подряд по одной строке клавиатурной раскладки в прямом или обратном направлении.

Например:

```text
qwe
ewq
```

Встроены две раскладки:

```text
qwerty
jcuken
```

Кроме встроенных раскладок можно подключать собственные таблицы, указав путь к файлу непосредственно в `layouts`:

```yaml
sequences:
  keyboard: 3
  layouts:
    - qwerty
    - layouts/custom.txt
```

Файл пользовательской раскладки является текстовым UTF-8 файлом. Каждая непустая строка файла описывает один ряд клавиатуры.

Например, файл `layouts/custom.txt`:

```text
1234567890
qwertyuiop
asdfghjkl
zxcvbnm
```

Для такой таблицы последовательности:

```text
123
321
asd
dsa
```

будут считаться клавиатурными последовательностями при `keyboard: 3`.

Пустые строки в файле раскладки игнорируются. Переход с одного ряда клавиатуры на другой последовательностью не считается.

Если указанный пользовательский файл не существует, не читается, содержит некорректный UTF-8 или не содержит ни одного непустого ряда, подготовка политики завершается ошибкой.

Встроенные имена `qwerty` и `jcuken` интерпретируются как встроенные таблицы; остальные значения в `layouts` интерпретируются как пути к пользовательским файлам раскладок.

## Словарь

```yaml
dictionary:
  path: dict/common.txt
  min_length: 4
  case_insensitive: true
  leet: true
```

Запрещается подстрока длиной не меньше `min_length`, совпадающая со словом словаря.

При:

```yaml
case_insensitive: true
```

регистр не учитывается.

При:

```yaml
leet: true
```

используются подстановки:

```text
4 -> a
3 -> e
1 -> l
0 -> o
5 -> s
$ -> s
@ -> a
7 -> t
```

Словарь читается построчно. Пустые строки и строки короче `min_length` пропускаются.

Поиск выполняется по заранее построенному префиксному дереву или автомату, а не полным перебором словаря для каждой подстроки.

## Контекст

Значения контекста передаются повторяемым флагом:

```text
--context key=value
```

Пример:

```bash
pwp check \
  --policy policy.yaml \
  --password-file password.txt \
  --context login=svc-01
```

Запрещается подстрока значения контекста длиной не меньше `forbid.context.min_length`, а также такая подстрока, записанная в обратном порядке.

К контексту применяются те же правила регистра и leet, что и к словарю.

## Диагностика

Для каждого нарушения указываются:

* правило;
* позиция;
* длина нарушающей подстроки.

Сама нарушающая подстрока в диагностику не выводится.

# Стойкость политики и стойкость отдельного пароля

Оценивается стойкость **политики**, а не отдельного конкретного пароля.

Пароль является одним значением, тогда как энтропия является свойством процесса, который этот пароль породил.

Нижняя граница энтропии политики рассчитывается на основе:

1. количества возможных исходов генерации до применения запретов;
2. эмпирически измеренной доли кандидатов, отброшенных правилами.

Оценка имеет вид:

```text
log2(число исходов) + log2(1 - доля отбраковки)
```

Результат выводится в битах с одним знаком после запятой.

Если точное число исходов определить нельзя, используется заведомо меньшая оценка, чтобы результат не завышал стойкость политики.

Команда:

```bash
pwp entropy --policy <file>
```

# Выдача, история, срок действия и ротация

## Пул предгенерации

Размер пула задаётся:

```yaml
issue:
  pool_size: 16
```

Пул заранее подготавливает пароли в буфере ограниченного размера.

При остановке пул:

1. прекращает фоновые операции;
2. дожидается завершения горутин;
3. затирает невыданные пароли из буфера.

При смене политики буфер сбрасывается и заполняется заново по новой политике.

## История

История выдач хранится во встроенном key-value хранилище.

Запись содержит:

```go
type Record struct {
    Subject       string
    Salt          []byte
    Hash          []byte
    IssuedAt      time.Time
    ExpiresAt     time.Time
    PolicyName    string
    PolicyVersion string
}
```

Открытый пароль в history store не хранится.

Для каждой записи используется уникальная случайная соль длиной не менее 16 байт.

Hash рассчитывается с использованием:

```go
crypto/sha256
```

Все временные метки хранятся в UTC.

## Окно истории

```yaml
history:
  window: 5
```

Новый пароль сравнивается с последними `window` записями того же субъекта.

Для каждой исторической записи вычисляется hash нового кандидата с её солью, после чего выполняется constant-time сравнение.

Если найдено совпадение, кандидат отбрасывается.

Если попытки исчерпаны из-за истории, выдача завершается ошибкой:

```text
history_exhausted
```

с кодом `2`.

Окно истории учитывает последние записи независимо от их срока действия.

## Срок хранения

```yaml
history:
  ttl: 180d
```

Истёкшие записи удаляются командой:

```bash
pwp gc --store <dir>
```

При этом записи, входящие в защищённое окно истории, не удаляются: окно имеет приоритет над TTL.

## Ротация

```yaml
rotate_after: 90d
```

Определяет срок действия выданного пароля.

Команда:

```bash
pwp rotate --policy <file> --store <dir>
```

строит план ротации, содержащий:

* субъект;
* дату выдачи;
* дату истечения;
* причину.

`rotate` только строит план и не изменяет пароли.

Текущее время можно передать через:

```text
--now <RFC3339>
```

Если `--now` не задан, используется системное время.

# Обращение с секретом

Проект должен соблюдать следующие гарантии:

1. пароль хранится как `[]byte`;
2. после использования контролируемый буфер пароля затирается нулями;
3. пароль не попадает:

   * в журналы;
   * в тексты ошибок;
   * в аргументы командной строки;
   * в отчёты;
   * в сообщения panic;
4. сравнение чувствительных значений выполняется через `crypto/subtle`;
5. history store содержит только соль и hash, но не открытый пароль;
6. под Linux файлы хранилища и отчётов создаются с правами `0600`;
7. диагностика нарушений не раскрывает саму запрещённую подстроку.

Пароль для `check` и `explain` передаётся только через файл или stdin.

# CLI

Глобальный формат запуска:

```text
pwp [global options] <command> [options]
```

Глобальные параметры указываются перед командой.

Обязательные команды:

```text
pwp gen
pwp check
pwp explain
pwp audit
pwp entropy
pwp policy validate
pwp issue
pwp history
pwp rotate
pwp gc
pwp verify
pwp version
```

## Основные флаги

| Флаг              | Назначение                              |
| ----------------- | --------------------------------------- |
| `-h, --help`      | показать общую справку                  |
| `--policy`        | файл политики                           |

## Примеры

Проверка политики:

```bash
pwp policy validate --policy demo/policy.yaml
```

Оценка энтропии:

```bash
pwp entropy --policy demo/policy.yaml
```

Генерация:

```bash
pwp gen --policy demo/policy.yaml --count 5 --out -
```

Проверка:

```bash
pwp check \
  --policy demo/policy.yaml \
```

```bash
pwp explain \
  --policy demo/policy.yaml \

```

Audit:

```bash
pwp audit \
  --policy demo/policy.yaml \
  --input demo/passwords.jsonl \
  --report build/audit.json \
  --report-html build/audit.html
```

Выдача:

```bash
pwp issue \
  --policy demo/policy.yaml \
  --subject svc-01 \
  --store build/history \
  --out build/svc-01.txt
```

История:

```bash
pwp history --subject svc-01 --store build/history
```

Ротация:

```bash
pwp rotate \
  --policy demo/policy.yaml \
  --store build/history \
  --now 2026-12-01T00:00:00Z
```

Очистка:

```bash
pwp gc \
  --store build/history \
  --now 2027-06-01T00:00:00Z
```

Проверка store:

```bash
pwp verify --store build/history
```

Версия:

```bash
pwp --version
```

Также поддерживается команда:

```bash
pwp version
```

Подробный режим:

```bash
pwp --verbose version
```

`--verbose` выводит служебную информацию о запуске и завершении команды в stderr. Аргументы команды при этом не выводятся.

## Коды возврата

| Код | Значение                             |
| --: | ------------------------------------ |
| `0` | успех                                |
| `1` | содержательное несоответствие        |
| `2` | ошибка входных данных или выполнения |

Код `0` используется, например, когда:

* пароль проходит политику;
* audit не нашёл нарушений;
* ротация не требуется.

Код `1` используется, например, когда:

* пароль не проходит политику;
* audit нашёл нарушения;
* rotation plan непуст.

Код `2` используется, например, при:

* неразрешимой политике;
* исчерпании попыток;
* недоступном хранилище;
* некорректных параметрах CLI.

Запрос справки должен завершаться кодом `0`.

# Форматы отчётов

`audit` создаёт отчёты в двух форматах:

```text
JSON
HTML
```

Вход `audit` имеет формат JSONL:

```jsonl
{"subject":"svc-01","password":"..."}
{"subject":"svc-02","password":"..."}
```

JSON-отчёт содержит:

```text
report_version
policy
totals
violations
subjects
```

Пример:

```json
{
  "report_version": 1,
  "policy": "service-accounts",
  "totals": {
    "checked": 1204,
    "passed": 1031,
    "failed": 173
  },
  "violations": [
    {
      "rule": "length",
      "count": 44
    },
    {
      "rule": "class.special",
      "count": 88
    }
  ],
  "subjects": [
    {
      "subject": "svc-01",
      "passed": false,
      "rules": [
        "class.special",
        "dictionary"
      ]
    }
  ]
}
```

Пароли и их hashes в audit-отчёты не включаются.

HTML-отчёт формируется через `html/template` с экранированием значений.

Для одинакового входа JSON-отчёт должен быть побайтово одинаковым.

# Известные ограничения

Проект работает только в границах задания.

Не поддерживаются:

* обращения к сети и внешним сервисам проверки утечек;
* интеграция с каталогами учётных записей;
* автоматическая смена паролей в целевых системах;
* собственные криптографические примитивы;
* собственное шифрование history store;
* многопроцессный доступ к одному history store;
* HTTP API;
* графический интерфейс;
* diceware и генерация парольных фраз из словаря;
* восстановление пароля по hash;
* подбор паролей;
* хранение открытых паролей вне буфера пула в памяти;
* политика прав доступа и разграничение ролей.
